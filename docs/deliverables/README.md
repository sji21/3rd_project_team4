# LENS 필수 산출물 기획틀

기준 코드는 PR #17의 `efc3103`(`fix(generation): improve local LLM reliability and grounded validation`)이다.
이 폴더는 최종 제출물이 아니라, 제출물을 만들 때 사용할 목차·포함 범위·검증 기준을 먼저
고정한 작업용 기획틀이다.

## 2. 공통 작성 원칙

- 기준 커밋 SHA, 생성일, 작성자, 실행 환경을 모든 산출물에 기록한다.
- 법령·판례·기관 안내는 자료 성격을 구분하고, 출처 URL과 수집일을 남긴다.
- 사용자가 업로드한 등기·계약서와 개인정보가 포함된 OCR 원문은 제출하지 않는다.
- API 키, `.env`, 로컬 경로, 개인 계정 정보는 제거한다.
- 평가 수치는 실행 결과 파일과 재현 명령이 있는 값만 기재한다.
- 판례 요약문 기반의 오염된 평가는 검색 성능 수치로 홍보하지 않는다.
- ZIP에는 `README.md`와 `checksums.sha256`을 넣어 구성과 무결성을 확인할 수 있게 한다.
- 최종 ZIP을 새 폴더에 풀어 설치·실행·테스트하는 제출본 스모크 테스트를 수행한다.

## 3. PR #17 기준 현재 상태

| 영역 | 현재 구현 | 산출물 반영 원칙 |
| --- | --- | --- |
| 화면 | Streamlit 법률 챗봇 | 현재 실행 화면으로 표시 |
| 검색 | 법령·판례·기관 안내 분리, BM25 + Dense + RRF | 세 코퍼스와 반환 개수를 구분해 표현 |
| 생성 | 로컬 Ollama `qwen3:8b-q4_K_M`, `max_tokens=256`, `num_ctx=4096` | 로컬 LLM 구성과 제한을 명시 |
| 검증 | 출처·숫자·조건 결정론 검사 + 의미 검증 | ANSWER/ABSTAIN/REFUSE 흐름에 포함 |
| 안내 | 질문 주제에 따라 0~2건 | 법적 근거가 아닌 실무 참고로 표시 |
| 문서 점검 | 등기·계약서 OCR 및 규칙 코드 존재 | 현재 챗봇 UI와 미연결임을 구분 |
| 평가 | Dev/Holdout 및 검색·생성 평가 도구 존재 | 검색 평가와 생성 E2E를 분리 보고 |

## 5. 작업 순서

1. 기준 커밋과 데이터 스냅샷을 동결한다.
2. 데이터 패키지의 manifest·건수·체크섬을 만든다.
3. 동결된 구조를 기준으로 아키텍처 그림을 확정한다.
4. README와 실행 환경을 정리한 소프트웨어 ZIP을 만든다.
5. 같은 ZIP과 데이터로 테스트를 재실행해 결과 보고서를 완성한다.
6. PDF·ZIP 파일명과 내부 파일을 최종 점검한다.
