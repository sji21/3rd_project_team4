# 민법 임대차 조문 추가 — 적용 가능성 검토 (2026-09-01)

주택임대차보호법만으로는 근거를 찾기 어려운 생활형 질문(시설 고장, 수리비
부담, 일부 사용 불가, 차임 연체)을 다루려고 **민법 임대차 핵심 조문 몇 개를
법령 코퍼스에 추가하는 안**을 검토했다. 넣을지 정하기 전에 확인한 것은 두
가지다 — **넣을 수 있는가**, 그리고 **넣으면 기존 것이 깨지는가**.

결론부터: **넣을 수 있다. 다만 1순위 5조문(`min5`)을 법령 코퍼스 전체에 항상
노출하는 방식은 권장하지 않는다.** 기존 평가셋(dev 27문항)의 정답은 하나도
잃지 않지만, 평가셋 밖의 일반 질문에서 **생성 근거가 실제로 바뀌는 회귀**가
확인됐다. 조건부 라우팅을 전제로 한 **조건부 채택 후보**로 본다.

재현:

```bash
python scripts/compare_minbeop_corpus.py --out data/eval/runs/minbeop_compare.json
```

저장소의 DB·인덱스·청크 파일은 건드리지 않는다. 지식 DB를 임시 폴더로 복사해
거기에만 적재하고, Chroma 대신 메모리 임베딩으로 변형끼리 비교한다.

## 1. 적재 가능성 — 문제 없음

국가법령정보센터 민법(`lsiSeq=284415`, 시행 2026-03-17, 법률 제21454호)을
기존 `fetch_law_mock` 파서로 받았다. 1,116개 조문이 정상 파싱됐고 검토 대상
10개 조문 전부 `LawArticleRecord.validate()` 를 통과했다.

`load_laws` → `export_chunks` → `validate_chunks` 까지 그대로 통과한다.
스키마 변경도, 검색 코드 변경도 필요 없다. `doc_type` 이 `law` 라
`Corpus("법령", ("law","decree","rule"))` 에 자동으로 들어간다.

생성되는 청크는 기존 조문과 같은 모양이다.

```
[민법 제623조(임대인의 의무)]
임대인은 목적물을 임차인에게 인도하고 계약존속중 그 사용, 수익에 필요한
상태를 유지하게 할 의무를 부담한다.
```

`article_id` 는 `민법-제623조` 로, 평가셋 gold 라벨에 그대로 쓸 수 있다.
판례·안내 청크와 `chunk_id` 충돌은 없다.

**다만 코드 수정이 한 건 필요하다.** `fetch_law_mock.LAWS` 에 조문 필터가
없어 그대로 추가하면 민법 1,116조가 전부 들어온다. `only_articles` 필드를
더해 골라내는 5~8줄짜리 수정이 필요하다. 이번 검토에서는 스크립트 안에서
같은 일을 했다.

## 2. 회귀 영향 — 평가셋 정답은 무손실, 평가셋 밖은 아님

네 변형을 같은 임베딩 모델·같은 조건에서 비교했다.

| 변형 | 민법 조문 | 법령 청크 |
| --- | --- | --- |
| `base` | 없음 | 133 |
| `min5` | 제623·626·627·634·640조 | 138 |
| `min6` | `min5` + 제621조 | 139 |
| `max11` | 1·2순위 10개 + 제621조 | 144 |

### dev 27문항 (법령 gold 조문)

분모는 **법령 정답 29개만** 센다. `dev.jsonl` 의 `gold_articles` 31개 중 2개는
공식 안내 정답(`guide-국세청-미납국세열람`, `guide-HUG-전세보증금반환보증`,
각각 dev-017·dev-023)인데, 이 비교는 법령 묶음만 검색하므로(`k_guide=0`)
구조적으로 도달할 수 없다. 분모에 남기면 천장이 씌워진 수치가 나와 **민법
때문에 잃은 것인지 원래 못 찾는 것인지 구분되지 않는다.**

| 변형 | Recall@3 | Recall@5 | TOP3 구성 변동 | TOP5 구성 변동 |
| --- | --- | --- | --- | --- |
| `base` | 29/29 (100%) | 29/29 | — | — |
| **`min5`** | **29/29 (100%)** | **29/29** | **0문항** | 5문항 |
| `min6` | 29/29 (100%) | 29/29 | 2문항 | 6문항 |
| `max11` | 29/29 (100%) | 29/29 | 5문항 | 10문항 |

**정답 적중은 네 변형 전부 동일하다.** 단 하나의 gold 조문도 잃지 않았다.
법령 검색은 이미 100%라 민법 때문에 잃었다면 곧바로 드러났을 텐데, 그러지
않았다.

그러나 **TOP3 구성 교란은 조문 수에 비례한다.** `min5` 는 dev TOP3 를 전혀
건드리지 않는데, 제621조를 넣으면 2문항, 2순위까지 넣으면 5문항이 흔들린다.
정답은 남아도 생성 모델에 넘어가는 근거 3칸의 구성이 바뀐다는 뜻이다.

### 판례 홀드아웃 20문항 — 순위 변동 0건 (전 변형)

예상대로였고, 이유도 구조적이다. `DenseRetriever.search` 는 점수를 계산하기
**전에** `where` 필터를 적용하고, BM25 는 `split_by_type` 으로 미리 쪼갠
코퍼스를 본다. 법령에 무엇을 넣든 판례 순위는 움직일 수 없다.

## 3. 신규 20문항 — 공백 하나가 메워지고, 근거 하나를 잃는다

| 변형 | TOP3 변동 | 민법이 TOP3 진입 |
| --- | --- | --- |
| `min5` / `min6` | 7, 10, 13 | **7, 10** |
| `max11` | 4, 7, 10, 17, 19, 20 | 4, 7, 10, 17 |

**7번 — 의도한 효과가 정확히 나왔다.** "월세를 몇 번 밀리면 집주인이 계약을
끝낼 수 있나요?" 는 주임법에 직접 근거가 없어 검색이 갱신 규정만 내놓던
문항이다.

```
base : 주임법-제6조의3, 주임법-제10조의2, 주임법-제6조      ← 전부 갱신 규정
min5 : 민법-제640조(차임연체와 해지) 1위, 주임법-제6조의3, 주임법-제10조의2
```

**10번 — 실제 회귀다.** "계약을 다시 하고 싶으면 집주인에게 언제 말해야
하나요?" 에 민법 제640조(차임연체와 해지)가 3위로 들어와 주임법 제6조를
4위로 밀어냈다.

```
base : 주임법-제6조의2, 주임법-제6조의3, 주임법-제6조
min5 : 주임법-제6조의2, 주임법-제6조의3, 민법-제640조, 주임법-제6조
```

**생성 파트는 법령을 3건만 쓴다**(`DEFAULT_K_LAW = 3`,
`docs/retrieval-handoff.md`). 그래서 4위로 내려간 제6조는 순위가 한 칸
떨어진 것이 아니라 **생성 근거에서 사라진 것**이다. 질문은 갱신 요구 시기인데
그 자리를 차임연체 해지 조문이 차지했다. "경미한 순위 변화" 로 적었던 이전
판단은 틀렸다.

원인은 문서 길이로 보인다. 민법 조문은 본문 중앙값 **112자**로 주임법
(215자)의 절반이고, 제640조는 64자에 "계약을 해지할 수 있다" 가 들어 있다.
BM25 의 길이 정규화(`b=0.75`)가 짧은 문서에 유리하게 작동한다.

| 법령 | 청크 수 | 본문 중앙값 |
| --- | --- | --- |
| 민법 (신규) | 5~11 | 112자 |
| 주택임대차보호법 | 41 | 215자 |
| 주택임대차보호법 시행령 | 35 | 272자 |

**13번 — 민법과 무관한 간접 재배열.** 민법이 TOP3 에 없는데도 제6조의2 가
빠지고 제6조가 들어왔다. 후보가 하나 끼면 RRF 융합 순위가 연쇄로 밀리는 정상
동작이고, 기대 근거인 제6조의3 은 1위를 지켰다.

### 생성 근거에서 빠진 조문 — `min5` 기준 3문항

TOP3 밖으로 밀린 것은 곧 생성 근거에서 사라진 것이므로 따로 센다.

| 번호 | 빠진 조문 | 대신 들어온 것 | 판정 |
| --- | --- | --- | --- |
| 7 | 주임법 제6조 | 민법 제640조 | **개선** — 제640조가 이 질문의 정답이다 |
| 10 | 주임법 제6조 | 민법 제640조 | **회귀** — 제640조는 이 질문과 무관하다 |
| 13 | 주임법 제6조의2 | 주임법 제6조 | 중립 — 민법 무관, 기대 근거는 1위 유지 |

`max11` 은 같은 집계에서 5문항(4·7·10·17·19)이 근거를 잃는다. 17번은
제3조의7, 19번은 제3조의6 이 빠지는데 둘 다 민법과 상관없는 손실이다.

## 4. 권장 — `min5` 조건부 채택 후보

**무조건 전체 노출은 권장하지 않는다.** `min5` 는 얻는 것(7번)과 잃는 것(10번)이
같은 조문(민법 제640조) 때문에 동시에 생긴다. 제640조를 항상 노출하면 차임연체
질문에서는 이득이지만 갱신 질문에서는 손해다. 어느 쪽도 코퍼스에 넣고 빼는
것으로는 분리되지 않는다.

**조건부 라우팅을 전제로 채택하는 것이 안전하다.** 이 저장소에는 같은 문제를
푼 선례가 이미 있다 — `route_law_corpus()` 가 상가 법령을 기본 제외하고 상가
신호가 있을 때만 푼다(`src/retrieval/service.py`). 민법도 같은 방식으로 둘 수
있다.

| 질문 신호 | 노출할 민법 |
| --- | --- |
| (기본) | 없음 — 지금과 동일 |
| 고장·수리·누수·수리비·일부 사용 불가 | 제623·626·627·634조 |
| 월세·차임 + 연체·밀림 | 제640조 |

이렇게 하면 10번("계약을 다시 하고 싶으면…")은 연체 신호가 없어 제640조가
후보에 들지 않고, 7번("월세를 몇 번 밀리면…")은 들어온다.

**단, 라우팅을 넣기 전에 성능을 먼저 재야 한다.** 게이팅부터 넣고 재면
민법이 TOP3 에 든 것이 검색력 덕인지 낱말표를 그 질문에 맞춰 짠 덕인지
구분할 수 없다. 이번 측정을 게이팅 없이 한 이유가 그것이고, 그 결과가
게이팅이 필요하다고 말하고 있다.

- **2순위 5조문(`max11`)은 넣지 말 것.** 교란이 dev 5문항·신규 6문항으로
  커지는데 얻는 것이 없다. 근거를 잃는 문항도 3개에서 5개로 늘어난다.
- **제621조는 보류.** 주임법 제3조의2·제3조의4 가 본문에서 「민법」 제621조를
  인용하는데 코퍼스에 없어, 생성 평가에서 모델이 그 참조를 따라갔다가
  환각으로 잡힌 적이 있다(`docs/generation-eval-20260831.md` dev-006). 끊어진
  참조를 메운다는 논리는 맞지만, **검색 지표로는 손해만 보인다** — 신규
  20문항에 이득이 없으면서 dev 2문항의 TOP3 를 교란한다. 특히 dev-019
  ("임차인에게 불리한 특약") 에 제621조(임대차의 등기)가 2위로 들어오는 것은
  오탐이다. 조문의 "반대약정이 없으면" 이라는 문구에 걸린 것으로 보인다.
  넣을지는 dev-006 을 생성까지 돌려 환각이 실제로 사라지는지 확인한 뒤 정한다.

## 5. 이 브랜치의 성격 — 적재 패치가 아니라 사전 영향 분석

들어 있는 것은 측정 하네스·결과·이 문서뿐이다. 실제 적재에 필요한 다음은
**전부 없다.**

- `fetch_law_mock.LAWS` 조문 필터 (지금은 스크립트 안에서만 흉내냈다)
- `data/raw/law/민법-20260317.txt` 원문 저장
- 지식 DB·Chroma 실제 재적재
- 민법 조건부 라우팅
- 자동 회귀 테스트
- 생성 E2E 실행

## 6. 아직 재지 않은 것

- **생활형 질문 자체의 검색 성능.** 이번 신규 20문항은 전부 주택임대차
  질문이라 **실제로 검증된 민법 조문은 제640조 하나뿐이다.** 제623·626·627·
  634조는 법적으로 타당한 후보지만 "법적으로 필요하다" 와 "이 검색기에서
  개선된다" 는 별개다. 다음 문항을 평가셋에 추가해 재야 한다.

  - 보일러가 고장 났는데 집주인이 수리해야 하나요? (제623조)
  - 제가 먼저 낸 수리비를 집주인에게 청구할 수 있나요? (제626조)
  - 누수 때문에 방 일부를 쓰지 못하면 월세를 줄일 수 있나요? (제627조)
  - 집에 수리가 필요하면 집주인에게 알려야 하나요? (제634조)
  - 월세를 두 달치 밀리면 바로 계약이 끝나는 건가요? (제640조)

- **제640조의 요건이 생성 단계에서 보존되는지.** 조문은 "차임연체액이 **2기의
  차임액에 달하는 때**" 로 규정한다. "두 번 연체하면" 이 아니라 연체 **금액**이
  2기분에 이르렀는지가 기준이다. 검색이 제640조를 잘 찾아도 생성이 이 요건을
  뭉개면 틀린 답이 된다. 위 다섯 번째 문항이 그것을 보는 문항이다.
- **생성 단계 영향.** 근거 구성이 바뀌면 답변이 어떻게 달라지는지는 검색
  지표로 보이지 않는다.
- **범위 판정(scope gate).** 생활형 질문 일부는 `abstention._IN_SCOPE_CUES` 에
  수선·고장·누수·전대 관련 어휘가 없어 검색 이전에 Qwen 범위 판정으로 넘어간다.
  `SCOPE_JUDGE_SYSTEM` 의 ALLOW 목록에도 수선의무·전대가 없다. 생활형 질문을
  실제로 서비스하려면 이쪽을 먼저 봐야 한다.

## 7. 별건 — 판례 홀드아웃 gold ID 불일치

측정 중에 발견했다. 민법과 무관한 기존 문제다.

```
코퍼스 case_id : CASE-2025DA210305
홀드아웃 gold  : 75829, 117855, 118615 ...
교집합         : 0건
```

`case_holdout.check_gold_case_ids()` 가 이를 검사하므로, 현재 main 의 청크로
홀드아웃 평가를 돌리면 전부 미스가 된다. 이 문서의 판례 Hit 수치를 성능으로
읽으면 안 된다. 판례 담당 쪽 확인이 필요하다.
